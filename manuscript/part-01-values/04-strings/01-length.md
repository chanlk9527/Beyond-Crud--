# 一段文字到底由什么组成

需求里常写“最多 20 个字符”。这句话的问题不在于数字 20，而在于“字符”没有说明是哪一种单位。

程序处理一段文字时，至少会经过下面几层：

```text
字节序列 → Unicode 码点 → grapheme cluster → 屏幕上的字形
```

这几层经常被日常语言里的“字符”混在一起。把它们分开，字符串的长度、截断和光标移动才有明确含义。

## 字节：编码后的存储单位

计算机最终保存和传输的是字节。UTF-8 是把 Unicode 文本编码成字节的一种方式：

```text
A    → 1 个字节
猫   → 3 个字节
🙂   → 4 个字节
```

字节数描述的是传输和存储成本，不描述用户看到了几个字符。一个中文字符通常比一个 ASCII 字符占用更多字节；emoji 可能占用更多字节。HTTP 限制、文件大小和数据库字段容量经常关心的就是字节数。

## 码点：Unicode 给文字成分分配的编号

Unicode 为文字和符号定义了统一的编号，每个编号叫一个**码点**（code point）。例如：

```text
A   = U+0041
猫  = U+732B
é   = U+00E9
```

码点是抽象文本的组成单位，不是某种编码里的字节。`U+00E9` 经过 UTF-8 编码后会变成两个字节，但它仍然只是一个 Unicode 码点。

码点也不一定等于用户认为的一个字符。`é` 可以有两种表示：

```text
é    = U+00E9
 é   = U+0065 U+0301
```

第二种表示由普通字母 `e` 和一个组合重音符组成，所以包含两个码点；显示时通常仍然看起来是一个字母。

## grapheme cluster：用户一次编辑的文字单位

**grapheme cluster** 可以译作“字素簇”。它是 Unicode 文本分段规则定义的一组码点，通常对应用户看到的一个可编辑单元：按一次退格键会删掉它，光标通常也会在它的边界上移动。

上面的 `é` 虽然有两个码点，但通常是一个 grapheme cluster：

```text
é = [U+0065 U+0301]
```

emoji 更能说明这个区别。家庭 emoji：

```text
👨‍👩‍👧‍👦
```

它由多个 emoji 码点和零宽连接符组成，但通常作为一个 grapheme cluster 显示和编辑。旗帜 emoji 也常由两个地区指示符码点组成一个 grapheme cluster。

这里的“通常”很重要。grapheme cluster 是文本处理规则对用户感知边界的近似，不是对“一个真实字符”的语言学定义，也不保证等于一个字形或一个语义单位。不同字体、平台和输入法仍可能有显示差异。

## 为什么会出现三个不同的长度

看下面几类文本：

| 文本 | UTF-8 字节数 | 码点数 | grapheme cluster 数 |
| --- | ---: | ---: | ---: |
| `A` | 1 | 1 | 1 |
| `猫` | 3 | 1 | 1 |
| `é` | 2 | 1 | 1 |
| `é` | 3 | 2 | 1 |
| `👨‍👩‍👧‍👦` | 多个 | 多个 | 通常 1 |

因此，“长度”必须带着单位一起说：

- **字节长度**：编码后占多少空间；
- **码点长度**：包含多少个 Unicode 码点；
- **grapheme cluster 长度**：用户通常能独立编辑多少个文字单元。

它们没有一个是普遍正确的答案。协议大小需要字节长度，Unicode 文本分析可能需要码点长度，昵称和评论的输入限制通常更接近 grapheme cluster 长度。

## Java 里的一个常见误解

Java 的 `String.length()` 返回的是 UTF-16 code unit 的数量，不是码点数，也不是 grapheme cluster 数：

```java
String text = "🙂";

text.length();                    // 2：两个 UTF-16 code unit
text.codePointCount(0, text.length()); // 1：一个 Unicode 码点
```

即使使用 `codePointCount`，也只能得到码点数。对于 `é` 或家庭 emoji，还需要按照 grapheme cluster 规则分段，不能继续把码点数当成用户看到的字符数。

## 长度限制应该先写清楚单位

一个文本字段可以这样定义：

```text
标题：最多 80 个 grapheme cluster
传输：UTF-8
数据库：最多 320 个 UTF-8 字节
超限：拒绝提交，不静默截断
```

如果产品只关心数据库容量，就不需要把字节限制伪装成“字符数”；如果产品关心用户输入体验，就不能用 `String.length()` 直接代替用户感知字符数。

截断也必须使用同一套规则：按字节截断要保证结果仍是合法 UTF-8，按 grapheme cluster 截断要保证不拆开组合字符或 emoji 序列。下一节再讨论文字经过 UTF-8、接口和数据库往返时，怎样验证它没有被改变。
